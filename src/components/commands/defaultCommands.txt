# Eva — commands the assistant may run by name.
#
# Anything listed here runs immediately when the assistant asks for it, with no
# confirmation, so keep the list to things you are happy to have launched: a
# web page, a note, a pasted screenshot or any other text that reaches the model
# can ask for one of these by name.
#
# Anything NOT listed here can still run, but only after a dialog shows you the
# exact command and you approve it. Delete this file to turn the whole feature
# off (the assistant will not be able to run anything at all, even with a prompt).
#
# Format, one per line:  name = command
#
# * Several names for one command are fine, separated by commas. Matching
#   ignores case, spacing and punctuation, so "vscode", "VS Code" and "vs-code"
#   all find the same line, and a spoken "open vscode" works too.
# * Words after a name become arguments: "vscode ~/notes" runs `code ~/notes`.
#   They are only passed along when they contain no shell syntax (`;`, `|`,
#   `$(`, `>`) — anything else gets a confirmation dialog instead.
# * A command starting with https:// is a LINK, not a program: "search
#   capybaras" below opens your browser on the results. `%s` is replaced with
#   the words you said, properly escaped, so a link can never be talked into
#   running anything. Links never need a confirmation.
# * A `!` in front of a command READS ITS OUTPUT: "ls = !ls" means saying
#   "ls Downloads" runs `ls Downloads` and hands what it printed to the
#   assistant, which can then tell you the answer. Without the `!` the output
#   goes nowhere — right for a program you are opening, useless for one whose
#   whole point is what it prints. Only mark commands that finish on their own:
#   one still running after 10 seconds is stopped, and a command you approve in
#   the dialog can ask for its output with the checkbox instead.
#
# Every program on the right of an `=` below is installed on this machine, so no
# line here fails its pre-flight. Add your own the same way, or just ask for
# something that is not listed and approve it when the dialog appears.

# --- Commands whose point is their output -----------------------------------
# Two ways to get at what a command prints. The `!` form answers the question
# through the assistant; a terminal or a notification shows it to you directly.
ls, list files = !ls
disk space = !df -h /
uptime = !uptime
memory, free memory = !free -h
git status = !git -C ~/sites/openwhispr status --short
who is online = !who
#
# A launched command gets no terminal — it is detached so it can outlive Eva —
# so a full screen program (vim, top, ssh) has to bring its own, and a command
# that only prints text would print it into nowhere.
containers = ghostty -e docker ps
pods = ghostty -e kubectl get pods
htop = ghostty -e htop
dev server = ghostty --working-directory=$HOME/sites/openwhispr -e npm run dev
ip address = notify-send "IP" "$(curl -s ifconfig.me)"

# destroy the machine rather than do a job: `rm -rf /`, `rm -rf ~`, `mkfs`,

# ~/.ssh/authorized_keys.
#
# Keep the list to single, fixed actions. A `docker` or `git` line would let the
# model append its own arguments (only shell syntax is filtered there), which
# runs without a dialog — so "docker ps" is fine, "docker" is not.
